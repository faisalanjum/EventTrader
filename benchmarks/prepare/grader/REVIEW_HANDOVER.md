# Grader review handover — for Codex's independent review (Fable, 2026-10-03)

**What this is.** The code that scores a conversion route (tool output in the common route format) against the frozen golden set
(package 2, `FINAL_KEY_FOR_CODEX_20261003_2014`, `../golden/PACKAGE.json`; 1134's 457 answers unchanged, see `DESIGN.md` §26). Pure code, standard library only, no AI, no hard-coded document strings. It answers,
per key target and per field: preserved and correctly associated (pass), not (fail with a reason), or not resolvable (unresolved).
It does **not** rank tools and does **not** grade meaning fields (T4: `measure`, `sign`, `unit_interpretation`, `marker_meaning`
are reported `not_t1`).

**What the owner asked you to confirm.** (1) Correct output passes. (2) Missing text, wrong values, wrong associations fail.
(3) HTML, PDF and XML are handled fairly. Please do not weaken the key to make tools pass; do not read held-out answers.

## Run it (repo root, python 3.10+, no extra packages for the grader itself)
```
python3 -B -m unittest discover -s benchmarks/prepare/grader/tests -t .        # 193 tests, ~1.6 s
python3 -B -m benchmarks.prepare.grader.checks.real_pairs                       # 48 real-original variants, ~20 s
python3 -B -m benchmarks.prepare.grader.grade --route <run>/route --out <run>/graded   # grade one route (key defaults to golden/PACKAGE.json)
python3 -B -m benchmarks.prepare.grader.checks.why <run>/graded [check:reason]  # explain failures: key value vs what the route carried
python3 -B benchmarks/prepare/golden/check_package.py                           # the key is where PACKAGE.json says, byte for byte
```
Adapters (tool output → common format) run under each tool's own environment; see `README.md`. Graded runs used for the numbers
below are under `/home/faisal/prepare_work/grader_runs/` (development split only; held-out aggregates only).

## Known limits (stated, not hidden)
- E15: time scope is checked from the source mapping (rows between the time heading and the value must lie between them in the source); a route with dishonest anchors is caught by the anchor gate instead.
- E12: joins are read from the output's mapping and the source alone — pieces whose anchors touch (cells at one grid position, text units) read as one, every other join as a space; the key never chooses a join. A within-word split on page-region anchors, and touching bytes where the key prints two words (CSS may space them; the output cannot say), are reported **unresolved**, never a pass or a fail — in every field, the row label and the run-in heading included; spacing beside punctuation and symbols is reflow.
- E14: the grid is the declared representation; geometry is the separately declared screen-span route; an explicit association field is not built until a tool offers one.
- Visibility: a stated supported subset — inline `display`/`visibility`/`opacity` with keywords or numbers (declarations split outside quotes and parentheses before escapes are decoded, so an escaped `;` stays inside its value; `!important` honoured; a declaration is one complete `name: value`), HTML implied end tags (`p`, `li`, `dt`/`dd`, `td`/`th`, `tr`, table sections, `option` — every open element of those kinds down to the boundary closes, so a new `<tr>` closes the open `<td>` and the open `<tr>`), a slash on a non-void HTML tag closes nothing, a `<` opens a tag only before a letter or a slash (`Cost < 1%` is text), a word boundary comes only from an element that itself shows (a hidden block or a hidden `<br>` breaks nothing); checked against headless Chrome on Codex's rounds 4 to 9 cases. The same pass records struck-through runs for the source-formatting step: `<s>`/`<del>`/`<strike>` and CSS `text-decoration(-line)` — only **resolved** values count (`none`, `initial`/`unset`, `revert` = the tag's default, combinations of the line keywords with a line style); the last resolved declaration is in force (`!important` first), a tag's default yields to its own declaration, a strike propagates to in-flow descendants but not into atomic inline-level or out-of-flow boxes, a child's `none` does not cancel. Two certainties: a struck run is certified only when no stylesheet rule touches decorations at all (a rule can remove a strike: `struck_certain`); "nothing struck here" only when no sheet rule could add or force one (`plain_certain`); an unevaluated value (colours, lengths, `inherit`, functions, invalid tokens) or an `<s>` left open across a block withdraws both. The step writes a strike only under the first, drops a converter's claim only under the second, and otherwise leaves the converter's own claim (2 of 116 key sources carry sheet decoration rules). Checked against headless Chrome on 20 shapes and Codex's 12 + 12. Outside the subset the file is **uncertain**: stylesheet rules on hiding properties (escapes decoded), imported sheets, unevaluated values, an implied end tag that drops unclosed hiding inline elements (the browser rebuilds them around the new block), and text written directly inside a table skeleton (the browser moves it before the table). A document whose stylesheet rules can hide text, or whose inline `display`/`visibility`/`opacity` carries a value this scanner does not evaluate (a keyword outside the CSS lists, `var()`, `calc()`, escapes), is reported **uncertain** (coverage and anchor honesty not measured); on the 116 HTML key sources this happens to none. `<noscript>` content is read as visible. In XML mode the HTML skip list does not apply (`<title>` is an ordinary element) and a CDATA section is character data.
- Coverage measures **visible source text**; picture content is never measured by it — the `nothing_lost` gate says so and lists the files' picture counts (`pictures_not_measured`). Coverage and anchor honesty are **not measured** for files without a text layer (PDF/images) unless the route declares page sizes (bounds only); a gate with any unmeasured file does not pass.
- Heading recognition, note links, reference links and `kind` are **structure counts**, not pass rules.
- The linker places long texts in order and short texts between anchored neighbours; a fallback placement is flagged `out_of_order`, a picture's gap anchor is flagged `gap` and never counts as coverage. Approximate alignment (`pieced`) is anchor chaining — 20-grams unique on both sides, the longest order-consistent chain, maximal extension — never a full character diff; within 1 % of difflib's matched characters on the worst file at 500× the speed, and it never claims text the source lacks (what it misses counts as insertion).
- XML: `adapters/xml_fields.py` (standard strict parser, no field list) passes the 9 development XML cells with honest anchors; its stated scope: units in source order; an element with text of its own around child elements is read whole as prose (`mixed`) while its children stay fields that name the prose they stand `within` (the reading stream is the units held by no other; the gate checks that a held unit follows its holder inside its bytes), repeated leaves report their own place, a unit (`unit_printed`) counts only at the key's declared source place (unresolved without one), attribute values are not read and are counted in `not_read` per file, the containing instance is named by its start tag; the scanner reads XML through the same parser (CDATA literal, references decoded, no HTML hiding rules); the 21 other XML targets are stratified-control and held-out files, graded only when that split is run. The PDF route covers 14 development files.
- Frozen inputs: a run first verifies the key files and the targets file of every packet the answer key names — at the folder it will be read from; a packet name present in two folders is refused — against `FINAL_MANIFEST.json`, and refuses to grade if the manifest does not pin them or pins one that is missing; `run_facts.verified` is true only when the split catalog is pinned too (`catalog_sha256`). Package 1134 does not pin it, so its runs report `unverified: catalog not pinned` until the next package does; fixtures without a manifest run unverified and say so.
- Text at anchors: the gate certifies position (whitespace-free) **and** word/number boundaries (`boundary_equal`: same characters and the same words and numbers; spaces beside punctuation or symbols are reflow, not faults); a tool that splits or glues a word or number anywhere is counted (`boundary`). Pieced units are judged as a whole against the source read block by block (each span with its own whitespace, a separator wherever the source prints anything between spans): the same words and numbers inside blocks and across every join by the ordinary boundary rule, source order kept, the insertion derived from the blocks, never from the tool's own count, malformed or reordered blocks dishonest; any inserted text fails the gate for that file — added text is never certified, whatever its size.
- PDF positions: never certified (no independent page geometry); consistency with the route's declared sizes is reported apart. Each page anchor of a unit carries the tool's span of the text it holds (`charspan`) when the spans are consistent; the owner's page-break rule (e) passes only on that mapping (the key's text inside the span mapped to the key's page), is unresolved without it and fails on another page. The PDF route re-reads a native page group by full-page OCR only when Docling's own confidence grades its text layer POOR on parsing (`parse_score`), the group closed over units that span further pages, the re-read units spliced in page order with ids and references (`id`, `notes`, `links[].to` — never text or hrefs) renamed; a unit that would still straddle a re-read page is kept and marked `incomplete`, never dropped. Only a full success is OK (a partial conversion or re-read is PARTIAL with the tool's errors) and a cached run is reused only against its record (`adapters/cache.py`: source bytes, producing version and settings, every output's hash, outcome; removed before any rewrite, written after every output; the producing version is kept). OCR quality itself is not flagged by that confidence (ledger §17), so scanned pages keep the engine's reading. The shared Docling unit builder emits a table's attached captions and notes exactly once, at their place (round 12: 65 notes in three development PDFs had no unit).
- Table context (E13): admitted only when the key declares it with `byte_ranges` that each read the phrase and lie inside the table or its title block (between the declared title and the table's end); any other declaration stops the run as a key defect. Package 2 declares the SL Green lines (the title block is a separate layout table that precedes the data table). The three change-column records keep their `value`/`comparison` roles: Codex found the direction stated in the surrounding text. A compared column's heading must belong to the value's group (C2 after Codex's reproducer).
- Package declarations (R4, package 3): the frozen manifest may name a declarations file (`contract_declarations`, pinned like the key files); a target it excludes by a reviewed source anchor (page numbers) is `EXCLUDED` — nothing graded, counted apart, never a pass; a declaration that does not match the key stops the run; a block the key declares `image` is `APPROXIMATE` when converted (word error rate and the critical tokens that differ, by ordered comparison), never a pass; package 2 declares nothing.
- Review history: Codex's thirteen rounds and the package-2 verdict (`prepare_work/grader_review_codex_20261003/`) and the changes they caused are in `DESIGN.md` §21–§37; every probe script was re-run against this code (`FABLE_RESPONSE*.md` there, `codex_probes_live/`).

# Grader review handover — for Codex's independent review (Fable, 2026-10-03)

**What this is.** The code that scores a conversion route (tool output in the common route format) against the frozen golden set
(package 3, `FINAL_KEY_FOR_CODEX_20261004_0557`, active since `9ccfd7c19`, `../golden/PACKAGE.json`; the 457 answers of package 2 with the owner's decisions of 2026-10-04, see `DESIGN.md` §44; package 2 is history). Pure code, standard library only, no AI, no hard-coded document strings. It answers,
per key target and per field: preserved and correctly associated (pass), not (fail with a reason), or not resolvable (unresolved).
It does **not** rank tools and does **not** grade meaning fields (T4: `measure`, `sign`, `unit_interpretation`, `marker_meaning`
are reported `not_t1`).

**What the owner asked you to confirm.** (1) Correct output passes. (2) Missing text, wrong values, wrong associations fail.
(3) HTML, PDF and XML are handled fairly. Please do not weaken the key to make tools pass; do not read held-out answers.

## Run it (repo root, python 3.10+, no extra packages for the grader itself)
```
python3 -B -m unittest discover -s benchmarks/prepare/grader/tests -t .        # 396 tests, ~6 s (the Chrome ones and the tool ones skip without their environment; three Chrome-only cases exist only where playwright is installed: 393 elsewhere)

python3 -B benchmarks/prepare/golden/check_package.py                           # the key is where PACKAGE.json says, byte for byte
```

## Known limits (stated, not hidden)
- E15: time scope is checked from the source mapping (rows between the time heading and the value must lie between them in the source); a route with dishonest anchors is caught by the anchor gate instead.
- E12: joins are read from the output's mapping and the source alone — pieces whose anchors touch (cells at one grid position, text units) read as one, every other join as a space; the key never chooses a join. A within-word split on page-region anchors, and touching bytes where the key prints two words (CSS may space them; the output cannot say), are reported **unresolved**, never a pass or a fail — in every field, the row label and the run-in heading included; spacing beside punctuation and symbols is reflow.
- E14: the grid is the declared representation; geometry is the separately declared screen-span route; an explicit association field is not built until a tool offers one.
- Visibility: a stated supported subset — inline `display`/`visibility`/`opacity` with keywords or numbers (declarations split outside quotes and parentheses before escapes are decoded, so an escaped `;` stays inside its value; `!important` honoured; a declaration is one complete `name: value`), HTML implied end tags (`p`, `li`, `dt`/`dd`, `td`/`th`, `tr`, table sections, `option` — every open element of those kinds down to the boundary closes, so a new `<tr>` closes the open `<td>` and the open `<tr>`), a slash on a non-void HTML tag closes nothing, a `<` opens a tag only before a letter or a slash (`Cost < 1%` is text), a word boundary comes only from an element that itself shows (a hidden block or a hidden `<br>` breaks nothing); checked against headless Chrome on Codex's rounds 4 to 9 cases. The same pass records struck-through runs for the source-formatting step: `<s>`/`<del>`/`<strike>` and CSS `text-decoration(-line)` — only **resolved** values count (`none`, `initial`/`unset`, `revert` = the tag's default, combinations of the line keywords with a line style); the last resolved declaration is in force (`!important` first), a tag's default yields to its own declaration, a strike propagates to in-flow descendants but not into atomic inline-level or out-of-flow boxes, a child's `none` does not cancel. Two certainties: a struck run is certified only when no stylesheet rule touches decorations at all (a rule can remove a strike: `struck_certain`); "nothing struck here" only when no sheet rule could add or force one (`plain_certain`); an unevaluated value (colours, lengths, `inherit`, functions, invalid tokens) or an `<s>` left open across a block withdraws both. The step writes a strike only under the first, drops a converter's claim only under the second, and otherwise leaves the converter's own claim (2 of 116 key sources carry sheet decoration rules). Checked against headless Chrome on 20 shapes and Codex's 12 + 12. Outside the subset the file is **uncertain**: stylesheet rules on hiding properties (escapes decoded), imported sheets, unevaluated values, an implied end tag that drops unclosed hiding inline elements (the browser rebuilds them around the new block), and text written directly inside a table skeleton (the browser moves it before the table). A document whose stylesheet rules can hide text, or whose inline `display`/`visibility`/`opacity` carries a value this scanner does not evaluate (a keyword outside the CSS lists, `var()`, `calc()`, escapes), is reported **uncertain** (coverage and anchor honesty not measured); on the 116 HTML key sources this happens to none. `<noscript>` content is read as visible. In XML mode the HTML skip list does not apply (`<title>` is an ordinary element) and a CDATA section is character data.
- Coverage measures **visible source text**; picture content is never measured by it — the `nothing_lost` gate says so and lists the files' picture counts (`pictures_not_measured`: the pictures the scanner shows, see below). Coverage and anchor honesty are **not measured** for files without a text layer (PDF/images); a box that contradicts the route's own declared page sizes is no position at all (below); a gate with any unmeasured file does not pass.
- Heading recognition, note links, reference links and `kind` are **structure counts**, not pass rules.
- A table of the tool that is one table of the source — the same texts, each as often, in exactly one table on either side — is placed in that table only, row by row where the tool kept the table's rows (`anchor.table_places`, `DESIGN.md` §45); the source's tables are the scanner's own record (`Visible.tables`), which the screen step reads too. Its places are kept for its cells: no other item takes one. Tables or rows that read alike are not told apart.
- The linker places long texts in order and short texts between anchored neighbours; a fallback placement is flagged `out_of_order`; a picture unit stands at its own picture tag (`source_picture`: the tag it names by `src`, or the only one between its anchored neighbours) or has no place — never the gap between neighbours (`DESIGN.md` §46); a route's own `gap` anchor still never counts as coverage. Approximate alignment (`pieced`) is anchor chaining — 20-grams unique on both sides, the longest order-consistent chain, maximal extension — never a full character diff; within 1 % of difflib's matched characters on the worst file at 500× the speed, and it never claims text the source lacks (what it misses counts as insertion).
- XML: `adapters/xml_fields.py` (standard strict parser, no field list) passes the 9 development XML cells with honest anchors; its stated scope: units in source order; an element with text of its own around child elements is read whole as prose (`mixed`) while its children stay fields that name the prose they stand `within` (the reading stream is the units held by no other; the gate checks that a held unit follows its holder inside its bytes), repeated leaves report their own place, the field graded is the innermost at the key's position (a field inside prose, not the prose; the same bytes claimed twice is ambiguous → unresolved), a unit (`unit_printed`) counts only at the key's declared source place (unresolved without one), attribute values are not read and are counted in `not_read` per file, the containing instance is named by its start tag; the scanner reads XML through the same parser (CDATA literal, references decoded, no HTML hiding rules); the 21 other XML targets are stratified-control and held-out files, graded only when that split is run. The PDF route covers 14 development files.
- Frozen inputs: a run first verifies the key files and the targets file of every packet the answer key names — at the folder it will be read from; a packet name present in two folders is refused — against `FINAL_MANIFEST.json`, and refuses to grade if the manifest does not pin them or pins one that is missing; `run_facts.verified` is true only when the split catalog is pinned too (`catalog_sha256`). Package 1134 does not pin it, so its runs report `unverified: catalog not pinned` until the next package does; fixtures without a manifest run unverified and say so.
- Text at anchors: the gate certifies position (whitespace-free) **and** word/number boundaries (`boundary_equal`: same characters and the same words and numbers; spaces beside punctuation or symbols are reflow, not faults); a tool that splits or glues a word or number anywhere is counted (`boundary`). Pieced units are judged as a whole against the source read block by block (each span with its own whitespace, a separator wherever the source prints anything between spans): the same words and numbers inside blocks and across every join by the ordinary boundary rule, source order kept, the insertion derived from the blocks, never from the tool's own count, malformed or reordered blocks dishonest; any inserted text fails the gate for that file — added text is never certified, whatever its size.
- PDF positions: never certified (no independent page geometry); a box with no area, negative, beyond the route's own declared page size or on a page it never declared is a position that cannot be true (below). Each page anchor of a unit carries the tool's span of the text it holds (`charspan`) when the spans are consistent; the part of a unit compared at a key's place (page and region) is taken from that mapping before any comparison; a unit over several places with no valid mapping is unresolved (`page_map`); words the mapping puts elsewhere fail (`page`); the owner's page-break rule (e) passes when the mapped part holds the key's text in order (`continued`). The PDF route re-reads a native page group by full-page OCR only when Docling's own confidence grades its text layer POOR on parsing (`parse_score`), the group closed over units that span further pages, the re-read units spliced in page order with ids and references (`id`, `notes`, `links[].to` — never text or hrefs) renamed; a unit that would still straddle a re-read page is kept and marked `incomplete`, never dropped. Only a full success is OK (a partial conversion or re-read is PARTIAL with the tool's errors) and a cached run is reused only against its record (`adapters/cache.py`: source bytes, producing version and settings, every output's hash, outcome; removed before any rewrite, written after every output; the producing version is kept). OCR quality itself is not flagged by that confidence (ledger §17), so scanned pages keep the engine's reading. The shared Docling unit builder emits a table's attached captions and notes exactly once, at their place (round 12: 65 notes in three development PDFs had no unit).
- Table context (E13): admitted only when the key declares it with `byte_ranges` that each read the phrase and lie inside the table or its title block (between the declared title and the table's end); any other declaration stops the run as a key defect. Package 2 declares the SL Green lines (the title block is a separate layout table that precedes the data table). The three change-column records keep their `value`/`comparison` roles: Codex found the direction stated in the surrounding text. A compared column's heading must belong to the value's group (C2 after Codex's reproducer).
- Package declarations (R4, package 3): the frozen manifest may name a declarations file (`contract_declarations`, pinned like the key files); a target it excludes by a reviewed source anchor (page numbers) is `EXCLUDED` — nothing graded, counted apart, never a pass; its bytes are subtracted from required-content coverage only and reported as `excluded_chars`; a declaration that does not match the key stops the run. A block the key declares `image` is `APPROXIMATE` only where the comparison failed on the words themselves or passed (word error rate with reference/recovered/substituted/deleted/inserted words, every ordered edit, the critical differences — digits, Unicode currency or sign characters, a negation with the word it governs, a number with the word that follows it — and the other differences, kept): a wrong place, a strike, an unknown mapping, references, section path and block order stay strict, and a strict failure outranks the approximate reading. Package 2 declares nothing.
- Positions that cannot be true, of every kind (round 15): a byte span outside the source or malformed, a page box with no area, negative, not finite, beyond the route's own declared page size or on a page it never declared, a span of neither kind, any anchor value that is no list of places (a string, a number), a declared page size that is no size — the item loses its position: it locates nothing and is evidence of nothing in any lookup, also by text (only placed cells and units are consulted: row context, header rows, period columns, the XML instance's fields, text fallbacks). Text at such a position counts dishonest whatever flag the route gives it (`gap` exempts no text; a table's own envelope too); a textless item there (a picture the linker gave an empty gap) counts `unplaced`, apart; the page boxes among them stay visible as `bounds_inconsistent`. A picture is what the scanner shows — an `img`/`svg` opening tag outside comments, scripts, styles, templates and attribute values, not under a hidden subtree, a void element's own `visibility` read — never a tag in the raw bytes, and only where visibility is certain (`pictures` is `None` under a stylesheet rule); picture text without a position counts unanchored.
- Whole words and numbers (round 15): a phrase is contained only when its stretch begins and ends where a word or number of the carrier does (`note 1` is not in `note 10`, `250` not in `1,250`, `not own` not in `cannot own`; `3.7 %` and `(Revenue 10).` still match) — periods, qualifiers, notes, range evidence, page continuations, the reference phrase, the unit inside the value cell and the XML unit text; a footnote mark may touch a word (`Revenue1`) but never cuts a number (`1` is not in `2015`, `1,000`, `1.5`), and a comma group made only of the record's own marks is marks. Two blocks carried by one unit are ordered by the route's own data — the interval of mapped characters, or of cells in grid order (one grid position: the listing order) — with the pairs taken from the source's order including boxes side by side on one row; a contradiction fails both, no readable order is unresolved (`internal_order`).
- Numbers, canvases, characters and what the scanner cannot judge (rounds 16–17): a number is printed with its sign and its leading point (`10` is not in `-10`, `(-10)` or `-$10`; `5` not in `.5`). Before a number the text settles three cases only: a dash or plus glued to a word or number on its left joins or ranges (`COVID-19`, `5-10`); one that touches the number with nothing before it but a space or an opening bracket, and no number before that, is its sign; one standing free between two numbers ranges (`5 - 10`). Any other shape — free-standing before the number (`stock – 10,000,000 shares`, `1.01% - 2.00%`, `LIBOR + 3.8%`), glued to other punctuation (`11%-63%`, `x=-10`, `$-10`), touching the number after another number (`-23 -18`, `US2007 -0287831`) — is undecided by the text: the source decides. Where the key's own span prints the phrase, a dash or plus stands before it in the source and the route prints that same stretch, it is printed; where the source prints none there, or another one, it is not; with no such span, no source text or an uncertain reading the field is unresolved (`numeric_boundary`), never a guessed negative, never a pass. A stretch, a deleted footnote mark or a removed own piece takes a word or number whole or not at all; a currency symbol between sign and digits stays a piece (`$` in `-$506`); an unsigned number and its symbol are separate pieces, parentheses separable. The source's format fixes the kind of position (a PDF by page boxes with a positive page; elsewhere bytes or a picture file's box named by its whole identifier, never a base name); an unusable page declaration is still a declaration (a box must lie on a usable page); bytes with no text layer are not measured. Character references are read as the browser reads them (control characters and non-characters kept). The scanner reads a stated subset of HTML as Chrome shows it and says *uncertain* at the subset's edge (286 Chrome cases, every element of the HTML Standard's index among them: certain and different in none). Read as the browser reads them: the content of raw-text elements as literal text, never tags (`textarea`, `xmp`, `plaintext`; `iframe`, `noembed`, `noframes`, `noscript` not rendered); the elements the browser starts on their own line; a `</p>` that closes nothing and a `</br>` as breaks. Uncertain: SVG/MathML, a template, the fallback content of `audio`, `video`, `canvas`, `meter`, `progress`, `select`, `object`; a `content-visibility` other than visible; a stylesheet that can hide; a closed `details`; a `script`, `style`, `title`, `noframes` or `head` the author displays; a head holding anything the parser would move into the body; a table part with no table; a hiding paragraph left open before a table (the reading depends on the doctype); a hiding element the parser moves out of a table. Under an uncertain reading the gates count nothing that depends on it (impossible positions and text without a position still count). A picture is an `img`/`svg` tag in a subtree the hiding rules leave shown — whether it paints is beyond the scanner — and a unit's text there is not measured: never a mismatch, never a certificate (a route carrying a picture reading cannot pass the honest-anchors gate for that file). Limits: references without their semicolon and cp1252's five undefined bytes; hiding by clipping, positions or transforms; `noscript` content with scripts off; closing tags that cross a table cell; only Chrome was asked; struck elements are read apart from their neighbours and a `textarea`'s text as its box shows it (on purpose); a route file malformed beyond anchors and page declarations stops the run; source adjacency is read without regard to the scanner's certainty.
- What is not certified, added in round 19 (`DESIGN.md` §43). **Uncertain page:** one that carries a script (a `<script>` of any type, an event attribute, a framed document with a `src` or `srcdoc`: nothing is run, so no reading of the page is vouched for); a `<meta>` content security policy (it turns style attributes off) or refresh (it sends the browser to another page); a character reference in a link's `rel`, an `http-equiv` or the `align` of an element it floats (the parser decodes it, the scanner only in a style string); a writing mode on an element in the line or in a sheet (under `-webkit-` and `-epub-` too: an inline in another writing mode is a box of its own lines; on a block it changes nothing). **Strike certificates withdrawn:** an element with `display:contents` and a strike of its own; a `color`, `text-decoration-color` or `-webkit-text-fill-color` anywhere in the file that may paint nothing (`transparent`, an alpha that is not the literal 1, a form not evaluated: a line takes its element's text colour unless given its own); struck text under a negative `letter-spacing` or a `contain` (on its element or above it; on the page's own elements, in a sheet, or on a formatting element left open that the browser opens again: anywhere): its line may have no length — a table floated by `align` is a float, its parent's strike does not reach it. Stated, not followed: text clipped by several declarations together is still text, and so is its strike. **XML:** a reading is certified only complete and byte for byte, by one parser setting for the scanner and the cell grader (parameter entities are read as declared): an external subset or entity, a reference the parser passes over, an encoding it does not know, or text beyond ASCII that is not UTF-8 leave it uncertain and read as nothing, and the cell grader then leaves `value` and `row_label` `unresolved` (`source_reading`). None of these forms stands in a certified document of the 22,483 HTML and 4,377 XML documents of the completed census.

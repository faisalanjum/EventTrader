# Step 4 — Prove, freeze, review, and publish the EXP-5 kit

## Goal

Perform one final proof of the complete Steps 1–3 candidate, freeze its exact
identity, and—only after review and direct owner approval—commit and normally
push that exact kit.

This step proves the exam kit, not model quality. It makes no AI call, creates
no gold key, does not run EXP-5/EXP-6, does not switch V1 to V2, and does not
write to Neo4j.

## 1. Freeze the final denominator

Merge the verified Step 1–3 rows without creating new categories. Report:

- rows total/closed/open;
- exact changed, deleted, generated, retained, and protected paths;
- unknowns and owner decisions;
- 36 primary events plus the disabled contingency;
- every test/proof identity required by the changed import closure.

Required state is zero open rows, zero unexplained paths, zero unknowns, and
zero owner decisions.

A closed row may reopen only if current evidence proves owner drift, byte
drift, a false test, a missed reachable caller, or a real omitted behavior. The
visible count must change with the reason. Unrelated findings become separate
future work; no genuine in-scope defect may be hidden to finish faster.

## 2. Record and protect the candidate

Record full HEAD, index tree, all staged/unstaged/untracked paths, authority and
dependency hashes, runtimes, and every Steps 1–3 artifact hash.

The staged candidate must exclude unrelated local work, ignored files,
credentials, caches, raw paid responses, and machine-specific output. In
particular:

- `ChannelContract.md` and `15_CandidateFactPacket.md` remain byte-identical V1;
- `ChannelContractV2.md`, Final Design, Plan, and WorkOrder remain the pinned
  inputs unless Step 1 explicitly found an owner-approved correction;
- `XBRL/**` remains byte-identical;
- pre-existing status edits are included only through their own reviewed row;
- these four work-order files are included only if Step 1 explicitly classified
  them for publication.

Any fixed value, field, vocabulary, model arm, corpus member, contingency, or
threshold must point to its official owner or be mechanically derived from
one. Otherwise delete it or fail closed; never turn a convenient observation
into a rule.

Never use a broad `git add` in the dirty repository.

## 3. Rebuild the complete kit twice

From the same frozen authoritative inputs, build the complete kit in two clean
temporary locations using only the selected existing builders.

Compare programmatically:

- path set and ordering;
- every generated byte and SHA-256;
- every event and prompt hash;
- both disabled launch plans, roles, arms, call counts, caps, and status;
- checker, reply transport, matcher, Core-route, scorer, and manifest pins.

Required result: zero missing, extra, or differing output. No generated file may
be manually edited after the build. Volatile run-time fields belong to the
future approved run, not this reproducible preparation freeze.

## 4. Reconcile every owner once

Mechanically confirm:

| Behavior | Sole owner |
|---|---|
| fact/item/numeric field surfaces | committed Core V2 schema |
| staged public event duties | `ChannelContractV2.md` plus its code-bound contract test |
| meaning and text/XBRL ownership | `FINAL_DESIGN.md` |
| prompt/rules assembly | one shared EXP-5 builder |
| mechanical answer checking | one checker reusing Core schema/locator owners |
| raw exact reply transport | one existing launch transport |
| automatic fact matching | `driver/core/fact_match.py` |
| conversion/fusion/validation/accounting/planning | committed `run_event` dry-run path |
| EXP-5 measurements and bars | Plan/WorkOrder plus one scorer |
| pins and run records | existing manifest/lock machinery |

Require zero copied field lists, duplicate validators/matchers, semantic regexes,
keyword or exception lists, guessed defaults, and unnecessary wrappers. Each
retained file must have a real caller and prevent a named failure.

## 5. Prove the high-risk behavior classes

Reuse the focused tests from Steps 2 and 3. Add a test only for an uncovered
required branch. The final evidence must prove:

- exact V2 structure and rejection of every retired V1 field class;
- exact quote/part/occurrence and quote-local scale evidence;
- source text cannot change instructions;
- exact decimal preservation;
- complete 36-event and prompt populations with no leakage;
- missing/extra/duplicate/wrong-event reply refusal and no reply loss;
- lossless recorded-answer replay through Core with writes off;
- one-to-one matching, visible duplicates, and no silent unmatched row loss;
- honest abstention, grading, score, union, and invalid-rate accounting;
- every official threshold boundary and zero-confirmed-wrong safety gate;
- drift detection for each pinned input class.

For each negative class, keep a lawful positive control. Expected results must
come from independent fixtures/calculations, never the function under test.

Use existing mutation/corruption machinery to show the tests have teeth. One
representative mutation per rule-owning class is enough; do not create dozens
of duplicate mutations or a new proof framework.

## 6. Run one bounded final test chain

Derive the affected test denominator from the changed files and their imports
before running it. At minimum run, in dependency order:

1. Step 2 instruction/envelope/checker tests.
2. Step 3 prompt/launcher/transport/matcher/scorer tests.
3. Existing EXP-5 harness guards and no-semantic-pattern gate.
4. Existing manifest/pin and relevant mutation checks.
5. Import-derived affected Core V2 route, accounting, matching, fusion,
   validation, planning, and audit tests.
6. Existing V1 parity/protected-hash checks.
7. The exact established Driver regression command frozen by the Step 1 receipt
   and required by the existing release gate; add no unrelated repository suite
   merely to inflate the count.
8. The existing isolated no-credential/no-write check.

Record exact commands, test node identities, pass/fail/skip totals, every skip
reason, environment versions, and exact candidate tree. Every changed decision
branch and failure outcome must map to a test. A green count without identities
or a silent detector is not sufficient.

## 7. Prove no external action occurred

Run preparation tests with model credentials absent and launch execution
disabled. Required totals:

- AI/paid calls: 0;
- filing fetches: 0;
- Neo4j writes: 0;
- production activations: 0;
- V1 callers changed: 0.

Use real read-only data only where the reachable builder or test genuinely
depends on it. If a live query is required, record the exact query, cutoff,
result hash, and read-only transaction proof; compare relevant before/after
counts. Do not add a broad graph census when the kit never reads the graph.

Any attempted model call or write fails this step immediately.

## 8. Build and test the exact staged tree

Stage only the reviewed denominator. Record:

- `git diff --cached --name-status`;
- staged path count and each staged blob hash;
- exact staged tree hash;
- remaining unstaged/untracked state;
- secret scan and protected-file hashes.

Reconstruct that exact tree in isolation and rerun the bounded final chain.
Require the reconstructed tree hash to equal the staged tree, all manifest pins
to match, and no untracked file, cache, credential, or mutable local state to be
needed. Any staged-byte change invalidates the proof.

## 9. Independent final review

Codex verifies the exact staged tree against:

- the fixed row/file/test denominators;
- the authority and one-owner table;
- smallest/deletion-first design;
- no unauthorized semantic hardcoding, semantic regex/fuzzy/keyword matching,
  exception, or duplicate rule owner;
- complete lawful controls and fail-closed uncertainty;
- all 36 events and both disabled launch plans;
- raw reply, Core replay, matching, scoring, and manifest evidence;
- protected V1/authority/XBRL hashes;
- zero calls, writes, activation, and unrelated drift.

The only verdicts are `VERIFIED` or a bounded `CHANGES_REQUIRED` tied to the
staged tree hash. No style-only review or unrelated redesign is allowed.

## 10. Publish only after direct owner approval

After `VERIFIED`, Core presents the staged tree hash, exact paths, test results,
skips, zero-call/zero-write proof, and proposed commit/push target. Commit and
push require the owner's direct approval at that moment.

Then:

1. reconfirm the staged hash;
2. create one bounded EXP-5-kit commit whose tree equals the reviewed tree;
3. verify equality before pushing;
4. push normally—never force, rewrite, auto-rebase, or auto-merge;
5. verify local HEAD/tree, origin/main, and remote commit/tree identities;
6. include a non-circular status row in the reviewed commit: it identifies the
   containing commit as the freeze commit, records the final artifact-manifest
   hash, and marks K-fields preparation-ready while retaining the separate paid-
   call approval gate;
7. after the normal push, report the derived local/remote commit and tree hashes
   without editing the frozen kit.

If the remote moved, stop. Do not alter history automatically.

## Step 4 is complete only when

- Every Step 1–3 row is closed and the final denominator has no residual.
- The complete kit rebuilds byte-identically twice.
- Every behavior has one authoritative owner and every retained file has a real
  need/caller.
- No reachable V1 behavior, duplicate semantic logic, unnecessary layer, or
  semantic hardcoding remains in the kit.
- Every changed branch and failure outcome has a test and lawful control.
- All bounded final tests pass with every identity and skip accounted for.
- The exact isolated staged tree passes and matches the manifest.
- V1, authority files, and `XBRL/**` remain protected as required.
- No AI call, fetch, Neo4j write, activation, or switch occurred.
- Codex verifies, the owner directly authorizes, and the exact reviewed commit
  is normally pushed and remotely rechecked.
- A fresh session can find the final commit, tree, manifest, tests, and next
  gate from `WORKORDER_STATUS.md` alone.

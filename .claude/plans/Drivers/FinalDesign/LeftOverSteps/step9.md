# Step 9 — Finish Fiscal Source-Location Certification

## Goal

Certify Fiscal's remaining source-finding lanes on fresh, hidden, real-source
cases; enable only the lanes with zero observed wrong selections; and prove the
live V2 Fiscal command reaches Core with a complete outcome ledger and no graph
write.

```text
known, value-blind Driver anchor + one pinned source
→ Fiscal selects exact source evidence or no match
→ code re-pulls and verifies the selected evidence
→ Fiscal builds one V2 source event
→ Core's existing reader, admission, validation, fusion, and plan route
→ every request and emitted item accounted, graph unchanged
```

This is not a second Core reader. Core's reader turns raw event evidence into
facts and decides meaning. Fiscal's reader has a known Driver anchor and finds
where that same fact appears in one source. Fiscal never names, creates, merges,
validates, or writes a Driver.

The already-proven tagged 10-K/10-Q filing route remains code-only. This step
does not make that route depend on a model.

## Non-negotiable rules

* Build the smallest solution that satisfies current law. Delete or reuse
  before adding code.
* One rule has one production owner. No wrapper may restate a source query,
  response grammar, source verifier, Core validator, or outcome rule.
* Meaning belongs to Sonnet 5 at high effort. Code may prepare complete candidates,
  assign opaque IDs, parse structure, re-pull source bytes, verify identity and
  exact spans, count outcomes, and fail closed. It may not decide semantic
  sameness from labels, words, names, or patterns.
* Add no behavior-changing string, list, number, range, threshold, pattern,
  regular expression, exception, or vocabulary unless live authority or an
  official standard supplies it, or code mechanically derives it from one.
* Preserve every lawful source and answer. Unproved, ambiguous, stale,
  malformed, conflicting, or unsupported evidence returns no match or the
  existing fail-closed outcome; it is never repaired into an acceptance.
* Every eligible source candidate must be offered according to the frozen
  population rule. Hidden truth may not preselect the winning table, block,
  sentence, or occurrence.
* An extra selected fact is a wrong accept. A missed fact is a recall loss.
  Zero observed wrong accepts is mandatory; every miss and abstention remains
  visible.
* Numeric evidence must state the value. Fiscal never computes a percentage,
  derives a plug, or turns an unstated implication into a numeric fact.
* TDD is required for every behavior change: reproduce the failure through the
  real public path, add a nearby lawful control, make the smallest owner-level
  fix, and prove the test detects that rule.
* Cover 100% of changed behavior branches and exception outcomes. Line coverage
  is recorded but cannot replace branch, mutation, real-source, and public-path
  proof.
* Reuse existing test, transport, batching, and receipt owners. Add proof
  machinery only when no existing owner can prove a named completion condition.
* Bounded Sonnet 5 high-effort calls and exact public, free evidence retrieval
  need no separate owner or spending approval. Wider or open-ended harvests,
  source purchases, separately metered services, Neo4j writes, and activations
  retain their exact authority. Completed-step commits and normal pushes follow
  the master ruling.

## 6. Define the smallest request and result contracts

The isolated capability request contains only:

* a stable request ID;
* one Core-rebuilt, metric-only, value-blind, target-period-free Driver anchor;
* one complete source unit from the frozen population;
* opaque candidate addresses assigned mechanically to all eligible evidence;
* the minimum source metadata required by the live source contract.

If the existing production runner batches anchors, its envelope may carry
multiple complete capability requests without changing any request's meaning.
The batching owner must preserve request IDs, full source fan-out, response
isolation, and one-to-one accounting. Do not add a second batching format.

The anchor may carry only the identity and retrieval clues authorized by
`rebuild_anchor`: company, Driver, metric fact type, slice, measurement,
series unit, time type, frozen wording clues, and an active concept clue when
lawfully present. It must not carry the target value, target period, answer ID,
hidden key, later evidence, or a truth-derived hint.

For each request, the model returns only the lane's exact source address set or
the frozen no-selection form. It does not return trusted values, quotes, units,
periods, source hashes, Driver names, or Core fields. Code re-pulls all evidence
from the pinned source.

For tables, code assigns opaque addresses only to source-parser-confirmed
numeric data cells. It must not use the anchor, labels, hidden key, or expected
answer to decide which numeric cells receive addresses.

The mechanical verifier must:

* parse the exact frozen result schema and reject added, missing, duplicate,
  unknown, padded, or wrong-typed fields/IDs;
* bind every ID to the same request and pinned source;
* re-pull source bytes and require the frozen hash and stable source address;
* reconstruct the exact cell, occurrence, or contiguous span;
* preserve sign, unit marker, scale marker, row/column labels, speaker, and
  source order as source evidence—not interpret their meaning;
* reject a model-written quote or evidence field rather than trust it;
* produce the existing no-match/invalid/verifier-conflict outcome without a
  fallback guess;
* emit each selected source occurrence once and account for all selections.

For text numeric facts, any unit/scale evidence later used by Core must be
inside the exact contiguous quote; extend the quote contiguously or abstain.
For structured tagged facts, Fiscal passes source metadata and leaves
`unit_scale_evidence` null; Core's structured path owns unit/scale proof.

Do not force one response schema onto all five groups if doing so adds unused
fields or weakens proof. Share only genuinely identical mechanics.

## 7. Write failing tests before production behavior

Before enabling a model-backed branch, add tests through the real Fiscal and
Core public paths for:

### Request integrity

* one real lawful anchor/source request;
* missing, blank, padded, duplicate, unknown, and wrong-typed request IDs;
* target value, target period, answer ID, or hidden-key leakage;
* stale, changed, missing, duplicated, or reordered source parts;
* equal text on two different source nodes, which must remain distinct;
* source material published after the event cutoff;
* incomplete source fan-out and a lawful complete control.

### Model output

* exact lawful selection and lawful no selection;
* one wrong extra selection;
* one missing keyed selection;
* duplicate, unknown, cross-request, cross-source, and out-of-range IDs;
* malformed JSON, extra prose, missing fields, added fields, wrong types,
  truncation, timeout, and model error;
* conflicting first and escalated responses;
* repeated wording with correct and wrong occurrence addresses.

### Source reconstruction

* original source unchanged and tampered after request creation;
* exact numeric cell, row/column context, sign, unit, and scale marker;
* long blocks and boundary occurrences;
* hidden elements, malformed markup, unsupported table shape, and encoding
  refusal through the existing parser owner;
* prepared remark versus analyst question;
* Q&A management answer versus question-only evidence;
* numberless claim versus nearby unrelated numbers;
* same label with different slice, measurement, unit, time type, or period;
* a stated value versus a derived percentage, plug, or merely implied value;
* source-local evidence versus a later corroborating filing.

### Public outcomes

* one raw input produces exactly one terminal or retryable ledger outcome;
* each source-location request has exactly one response status, and each
  verified selected occurrence becomes exactly one raw item with one Core
  outcome;
* accepted evidence reaches the Core V2 route once;
* no selection, invalid response, verifier conflict, source drift,

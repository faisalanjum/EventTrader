## First-principles challenge of the current baseline

- **A source location is not a forecast record.** The common-path run created 53 targets: 16 numeric occurrences and 37 sentence targets. Range endpoints and their containing sentence can describe the same fact. This inflates field questions before complete-record identity is established. Any safe deduplication must preserve different measures, units, periods and scopes; longest-overlap deletion is not a solution.
- **Fix identification before adding reasoning.** Earlier successful tagged tests included both the literal source text and its occurrence ID in each question. The new B test used the ID alone and misclassified some years/forecast amounts. A matched literal-plus-ID diagnostic is prepared; its result is not yet known. This is an input-binding hypothesis, not proof of a model defect or a reason for another extraction layer.
- **Order work by prerequisites and measured cost.** The baseline asks nine full-context field/presence questions before trying the three required local copies. If required measure/value copying is empty, the later answers cannot rescue a complete record. Test cheap required copying before expensive interpretation, and exact-occurrence deduplication, only after seeing the whole baseline. Do not change the running configuration mid-test.
- **Do not rebuild a text writer without acknowledging the cost.** This checkpoint has decision and span heads, not a generative language head. Word choices can copy source text, but counting, selecting positions and resolving remote references add rounds. Their isolated successes do not establish a smaller complete extractor.
- **Extraction failures differ from representation gaps.** Centre-plus-tolerance, event-relative target periods and ambiguous relative bounds can be present in the text but lack a verified normalization in this trial. Preserve and count them; do not invent precision or blame every hold on Locate. Rulebook changes are outside this task.

The binding comparison must use two matched requests, not both variants in the same isolated batch: native `question_layout` lets the shared context attend all question blocks, so an ID-only question can indirectly receive the literal value from the paired question. The prepared test was corrected before running. Choice keys with `None` descriptions ARE shown to the model (`protocol.options`); shared-menu rendering is not an omitted-options bug.

## Tiers within each document

1. **Content first:** account for every original section/table, including appendices; compare words, numbers, signs, units, dates, qualifiers, omissions, additions and legitimate repetition.
2. **Meaning and connections:** check reading order, headings, row/column/header associations, spans/nesting, lists, captions, footnotes, continuations and picture placement. Preserve grouping when the original does not define a unique order; do not invent an author-intent requirement.
3. **Traceability and completion:** check source references against the original and saved pieces, XML structure where applicable, all included picture occurrences, and explicit missing/partial/error outcomes. Unread regions remain listed as incomplete.

These tiers set priority **within one section-by-section comparison**, not three whole-document reading passes. Finish with the whole-document coverage and cross-section relationship check. A document is not fully reviewed until all applicable tiers are covered. The original supplies the section/table inventory, so an omission in extraction cannot disappear from the review checklist. Review original to reconstruction for omissions, and reconstruction back to original for additions, duplication and wrong attachment. For HTML layout use the existing browser's display of the original with its available styles/assets; markup or style declarations alone do not prove displayed order. XML is compared against original element/attribute/mixed-content structure. Picture connections use the actual asset and occurrence; OCR reading remains excluded. No new renderer is required. ## Prevent the predictable loops

- **Long documents/context limits:** continue through named, contiguous sections with overlap at table/footnote boundaries; carry global relationships forward. Search results, truncated tool output and summaries are not complete reads. Never silently truncate, summarize unread pages or mark a partial read complete. Size the output view from the actual document; do not assume a fixed small report size.
- **False reassurance/model agreement:** write an independent first judgment before reading another agent's conclusions. Use the single clean-content recheck allocation above. Agreement alone is not proof; disagreements are resolved against the original, not by majority vote.
- **Missing input or tooling problem:** one bounded diagnosis, then record the affected document as incomplete and continue other independent documents. Keep failed selections in the campaign. Do not invent replacement content or build general recovery machinery.
- **Large shared defect:** pause only affected reviews, fix its owner once, and retest that class. Do not spend each document's budget rediscovering the same failure.
- **Cosmetic differences or speculative cases:** no repair unless meaning, required structure or provenance is affected. An optional diagnostic field's uncertainty does not create a new requirement. Old-schema missing fields and the collator's existing unknown associations are reviewed for actual required information loss, not turned into a universal new wrapper gate. Report a genuine minor keep/cut tradeoff once; do not make it an endless background task.
- **Changing outputs/sample:** retain source, output and code identity per batch. A repair creates a new candidate and preserves the first result. New final failures are retained; no repeated selection until a clean panel appears.
